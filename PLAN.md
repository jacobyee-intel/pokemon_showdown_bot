# Pokemon Showdown Bot Implementation Plan

## Goal

Build a self-play reinforcement-learning bot for current Generation 9 Random Battles using the canonical Pokemon Showdown simulator and a PyTorch policy/value model.

## Implementation Order

1. **Scaffold the repository**
   - Add TypeScript and Python tooling.
   - Add the initial source, test, configuration, and artifact directories.
   - Define standard build, test, training, and evaluation commands.

2. **Pin Pokemon Showdown**
   - Add Pokemon Showdown at a fixed commit.
   - Record the revision so simulations and tests remain reproducible.
   - Define a controlled process for updating to newer Random Battle data.

3. **Run one seeded Gen 9 Random Battle**
   - Create a minimal random-versus-random battle.
   - Capture the player requests and protocol events produced by a complete battle.

4. **Save protocol fixtures**
   - Capture representative move, forced-switch, wait, Terastallization, Struggle, Revival Blessing, faint, win, loss, and draw cases.
   - Use these fixtures for deterministic unit tests.

5. **Finalize observation schema v1**
   - Define the perspective-safe battle observation.
   - Define the 14 action candidates and legal-action mask.
   - Define agent request, agent response, and terminal-result messages.
   - Validate the schema in both TypeScript and Python.

6. **Implement the action adapter**
   - Map indices 0-3 to move slots 1-4.
   - Map indices 4-7 to move slots 1-4 with Terastallization.
   - Map indices 8-13 to switch or Revival Blessing targets.
   - Derive legality exclusively from the current Showdown request.
   - Translate selected indices back into valid Showdown commands.

7. **Implement the perspective-safe state tracker**
   - Track the player's complete team, moves, PP, stats, item, ability, and Tera types.
   - Track only publicly revealed opponent information.
   - Track HP, status, boosts, volatile effects, side conditions, weather, terrain, Trick Room, and Tera usage.
   - Maintain stable public Pokemon identities.

8. **Test information isolation**
   - Change hidden opponent team information and verify that the player's observation remains unchanged.
   - Cover Illusion and other mechanics that intentionally alter public information.

9. **Complete 1,000 masked random battles**
   - Select actions only through the 14-action legal mask.
   - Require zero invalid actions, crashes, hangs, and hidden-information leaks.
   - Verify reproducibility from fixed seeds.

10. **Build evaluation infrastructure**
    - Implement fixed random and heuristic opponents.
    - Run paired evaluations by swapping the same generated teams between agents.
    - Report win rate, confidence intervals, battle length, decisions per second, and battles per second.

11. **Implement Python observation encoding**
    - Build stable vocabularies for species, moves, items, abilities, types, statuses, and effects.
    - Include reserved unknown values so simulator updates do not invalidate checkpoints.
    - Convert observations into Pokemon, side, field, action-candidate, and legal-mask tensors.

12. **Implement the initial policy/value model**
    - Begin with a shared per-Pokemon encoder and team pooling.
    - Produce 14 policy logits and one expected-outcome value.
    - Keep model capacity small enough for efficient batched inference on an RTX 3050.

13. **Connect Node and Python**
    - Run long-lived simulator workers.
    - Initially exchange newline-delimited JSON messages.
    - Batch observations for GPU inference.
    - Surface protocol and worker errors without silently recovering.

14. **Run complete battles with the untrained model**
    - Verify tensor encoding, legal masking, action sampling, command translation, and terminal handling.
    - Ensure wait requests do not create model decisions or rollout transitions.

15. **Implement trajectory collection**
    - Store observations, legal masks, actions, old log probabilities, value estimates, rewards, terminal flags, and policy versions.
    - Keep rollout storage in CPU memory.
    - Train the actor only from decisions generated by the current policy.

16. **Implement and test PPO**
    - Add generalized advantage estimation.
    - Add clipped policy loss, value loss, and entropy regularization.
    - Add checkpointing and training resume support.
    - Begin with terminal rewards: `+1` for a win, `-1` for a loss, and `0` for a draw.

17. **Train against fixed baselines**
    - First verify that the policy learns to beat the random agent.
    - Then require statistically significant improvement against the heuristic agent.

18. **Add historical-checkpoint self-play**
    - Maintain current, historical, random, and heuristic opponents.
    - Define checkpoint cadence, matchmaking weights, and promotion criteria.
    - Evaluate against a frozen opponent pool to detect forgetting and strategy cycling.

19. **Run model ablations**
    - Compare a flattened MLP, pooled Pokemon encoder, and small Transformer.
    - Give each model the same environment-decision and wall-clock budgets.
    - Compare held-out Elo, confidence intervals, sample efficiency, and throughput.

20. **Add advanced mechanics features**
    - Add damage ranges and accuracy-adjusted knockout probabilities.
    - Add entry-hazard calculations and speed-range estimates.
    - Add possible Random Battle set filtering and opponent beliefs.
    - Introduce each feature independently and measure its effect through ablation.

21. **Profile and optimize**
    - Batch GPU inference.
    - Increase concurrent battles per Node process.
    - Scale simulation across CPU cores.
    - Remove unnecessary protocol logging and serialization.
    - Consider Showdown's direct `Battle` API if simulation is the bottleneck.
    - Optimize inter-process communication only when profiling justifies it.
    - Add remote CPU actors only if local CPU capacity or laptop thermals limit training.

## Initial Delivery Boundary

Steps 1-9 form the first delivery milestone: a tested simulator that converts real Pokemon Showdown requests into perspective-safe observations and valid masked actions.

## Core Dependency Path

```text
Pin Pokemon Showdown
  -> capture real protocol fixtures
  -> finalize observation and action contracts
  -> implement state tracking and action masking
  -> complete masked random battles
  -> connect the PyTorch policy
  -> collect trajectories
  -> train with PPO
  -> add checkpoint self-play
  -> evaluate and optimize
```
